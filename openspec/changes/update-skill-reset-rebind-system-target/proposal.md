# Change: Update Skill Reset to Rebind System Targets

## Why
Current system skill reset does not reliably reset bound agent targets and may mutate whichever target is currently bound, including user-created targets. Reset confirmation UX is also too weak for a destructive operation, and some reset labels still fall back to raw i18n keys.

## What Changes
- Strengthen system skill reset semantics:
  - Always rebind reset scope to system default target (`<skill>__workflow` / `<skill>__agent`).
  - Reset that system target back to JSON baseline defaults.
  - Do not mutate user-created targets during reset.
- Apply same semantics to bulk reset (`reset-all`) for all system skills.
- After reset, clear target version history and keep only the publish version generated by this reset.
- Upgrade reset UX to a two-step destructive dialog with typed `RESET` confirmation.
- Fix and extend reset i18n keys (including `settings.skills.resetAll`) to avoid key leakage.
- Expand query invalidation after reset/reset-all to refresh skills, targets, and version panels.
